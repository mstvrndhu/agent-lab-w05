# Rejection: unsafe simulated file-organization plan

I would not approve this plan as written.

- **“Organize everything in Downloads” expands the scope** beyond a named practice folder. Limit work to an explicitly selected input folder and show the proposed file list first.
- **Deleting duplicates risks losing needed copies.** Keep every source file and make organized copies; report possible duplicates for a person to review.
- **Treating `final2` as latest assumes the answer from a filename.** Compare the contents and use dates only as supporting context, retain both versions, and flag which one needs a human decision.
- **Filling missing values with guesses would invent facts.** Leave unknown values blank or mark them “needs confirmation”; do not infer them.
- **Publishing automatically would expose files and take an external action without approval.** Prepare a local draft and ask for explicit review before any upload or publication.

## Acceptable alternative

Work only in the specified practice input folder. First inventory the files and propose categories without changing anything. After approval, preserve the originals, create copies in a new output folder, and write a report that lists duplicate candidates, conflicting versions, and missing information. Stop before deleting, guessing, or publishing; ask the user to review any ambiguous decision and approve any external sharing.
